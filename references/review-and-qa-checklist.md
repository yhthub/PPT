# 迭代修改管理协议与交付前四维质检清单

---

## 一、迭代修改管理协议（处理用户反馈时必读）

> **核心心智**：你修改的是一套相互关联的演示系统，而不是孤立响应最后一句反馈。每一次修订都必须同步回顾用户先前的历史要求，防止“改好后面、改坏前面”。

### 1. 每轮修订先划分三类清单
接到用户修改意见后，动手前先明确划分：
1. **锁定项（Locked）**：用户之前已确认满意、且本轮未要求改动的内容（如已定封面、特定页布局、白底规范、图形语义、配色系统）。**未经允许严禁擅自改动或顺手“重构美化”。**
2. **修改项（Target）**：本轮明确要求调整的页面、文案、逻辑、图表或视觉问题，拆解为逐条可验收的任务项。
3. **关联检查项（Ripple Check）**：本轮未直接点名、但可能受修改波及的要素——包括全套术语一致性、页码与右侧/顶部章节导航高亮、前后页承接关系、以及连续五页版式是否因插页/删页出现撞车。

### 2. 先诊断根因，再采取动作
- 听到 **“层次不清”**，依次排查：主次字号是否太接近？子内容是否离所属标题太远？信息组边界是否模糊？还是本页逻辑关系本身未理顺？
- 听到 **“空间浪费 / 太干瘪”**，先查内容是否缺关键依据、图表/截图是否偏小、现有节点能否自然向空白处展开，**绝不机械等同于“再塞一张插画”**。
- 听到 **“内容不够”**，先回溯源材料挖出真实细节、条件、证据或案例，**绝不凭空编造三个空洞要点凑满版面**。

### 3. 严禁擅自改变用户已确认的图形语义
- 若用户指定或确认了某种核心图形结构（如金字塔证据层级、特定系统架构划分），必须先看懂原图结构，保留其核心语义，只优化清晰度、风格统一性与文字可读性，**严禁未经沟通将其强行改成另一种流程图或卡片**。
- 修改局部文案时，不顺手重画已通过的插画；微调单个模块层级时，不擅自推翻整套视觉主题。

### 4. 逐项核对实际成品，不以“增页/改脚本”冒充完成
- 绝不能只因为增加了页数、或者修改了构建代码就声称“已完成”。
- 每次迭代后，必须核查**最终导出的实际文件**，并向用户清晰对照：
  - 新增了什么、修改了什么、保留/恢复了什么；
  - 每一条反馈具体落在哪一页并已渲染确认；
  - 若存在客观受限项（如原素材模糊/裁切），如实说明而非敷衍遮掩。

## 二、交付前四维全量质检清单

在向用户交付最终文件前，必须先将成品逐页渲染为预览图，按以下四个维度完成**缩略图全套连看 + 逐页放大核查**：

### 维度 1：内容与叙事逻辑
- [ ] **全套主线**：不看讲稿，仅串读所有页面主标题，能否清晰感受到论证层层递进？
- [ ] **非流程替代**：是否避免了把系统运行步骤直接等同于整场汇报大纲？
- [ ] **前后闭环**：开篇郑重提出的问题，后文是否逐一回应？结尾是否回扣开篇场景与核心问题（而非堆砌万能套话）？
- [ ] **单页结论**：每一页是否有明确的单行结论式主标题，而非泛泛的主题名词？
- [ ] **关系匹配**：是否按“信息关系 → 主导版式”选型，无为了做图而虚构的因果/时间/循环关系？
- [ ] **事实边界**：已完成事实、设计构想、未来展望是否严格区分？产品/AI 介绍是否区分“公司/模型/产品/平台/智能体”并写明限制与人工责任边界？
- [ ] **信息充实度**：正文是否做到详实不堆字、简洁不空洞？技术名词是否交代了作用与输入输出？架构与技术栈是否分层清晰？
- [ ] **数据严谨性**：所有外部数据、性能对比、版本价格是否核对官方来源，并标明比较对象、单位、条件与“以官方最新发布为准”提示？

### 维度 2：视觉系统与版式节奏
- [ ] **系统统一**：全套背景、字体、主辅语义色、圆角、描边、阴影、页眉/页脚、章节导航与页码是否高度一致？
- [ ] **连续五页无重样**：是否已落实《五页版式分配表》，确保连续 5 页主导结构零重复、相邻 3 页至少变化 2 项节奏维度？
- [ ] **视觉重心与比例**：每页是否有明确视觉重心（图形化页主视觉约占内容区 45%–70%，深度答辩页正式内容约保留 20%–30% 有组织留白）？
- [ ] **图文成组**：插画/图表/图标是否紧贴其解释文字，无“文字全挤左边、图标孤立右边”的割裂排版？
- [ ] **资产质量**：每页是否完成了合理的视觉资产决策，避免了整套纯文字线框页？介绍具体产品时是否置入了官方可核验品牌符号？
- [ ] **现代圆角与组件质感**：卡片、架构分层条、分段比例条与嵌套徽章是否告别了生硬 90° 直角砖块及“左圆右直”拼接缝？是否遵循同心圆角层级与轻柔和阴影/微描边（参考 Apple 前端卡片语言）？
- [ ] **插画/图标图文互文与质感门槛**：每张插画与图标是否呼应全套主题画风且紧扣本页文字辅助理解？是否由 Agent 自主写 Prompt 生图（无文字/无数字/无伪 UI、干净去底融纸）或采用高精专业图标，彻底杜绝粗糙简陋的程序手拼图形？
- [ ] **局部与全局协调**：架构图/图表内部的局部多色区分，是否兼顾了可辨识度与整套画风统一？

### 维度 3：排版与绘制细节
- [ ] **对齐精度**：同类模块是否等宽、等高、等间距；跨区域左边缘、标题基线、分隔线与连线端点是否对齐栅格？
- [ ] **连线合规**：连接线与箭头是否先于文字绘制、方向语义一致，且**零越界、零穿字、零断裂、零遮挡**？
- [ ] **文字无瑕**：主标题是否保持单行？全文是否零错别字、零乱码/缺字/方框字、零重叠、零被边框截断或超出画布？
- [ ] **图形图表无失真**：图表、卡片、时间轴、真实界面截图是否无压扁、无拉伸、无意外裁切？截图小字是否可辨认？
- [ ] **合规与隐私**：是否检查了匿名要求（如评审隐去敏感信息）及单位标识/校徽位置统一？

### 维度 4：文件与交付确认
- [ ] **原生可编辑性**：文字、形状、流程连接符均为 PowerPoint 原生可编辑对象（绝非整页位图冒充 PPT）；插画与图标至少可作为独立单元移动或替换。
- [ ] **SVG 一致性（如同步交付 SVG）**：SVG 含真实 `<text>` 与独立矢量图形元素，可在 PowerPoint 中“转换为形状、取消组合”继续编辑，且视觉与 PPTX 一致。
- [ ] **锁定项保全**：回顾本轮与历史反馈，确认所有用户已锁定内容未被破坏。
- [ ] **双版本验收**：保留可编辑母版源文件；若另行导出 PDF 或图片型展示版，已逐页核查导出后的清晰度、字体嵌入与边缘裁切。
- [ ] **版本与附件核验**：确认交付路径/文件名对应最新正确版本，所有外部资料来源已附说明，且如实汇报完成状态与已知局限。
